### 3.2 `baseline_dvfs.py` 实现内容

新增主要对象与接口：

- `FrequencyLevel`：描述频率档位，包括 `name`、`frequency_scale`、`voltage_scale` 和派生的 `power_scale`。
- `DvfsThresholds`：描述温度/电量阈值，包括 `T_warn`、`T_crit`、`E_warn`、`E_crit`。
- `DEFAULT_FREQUENCY_LEVELS`：默认三档 `high/medium/low`。
- `select_frequency_level(...)`：按热-电阈值选择频率档位。
- `scaled_power_w(...)`：按 `P_dvfs = P_high * V_q^2 * f_q` 计算缩放功耗。
- `progress_increment_slots(...)`：返回单时隙相对高频的任务进度比例。
- `FcfsDvfsScheduler`：固定 FCFS 队列的 DVFS 调度器。

频率选择规则：

```text
if T(t) >= T_crit or E(t) <= E_crit:
    q(t) = low
elif T(t) >= T_warn or E(t) <= E_warn:
    q(t) = medium
else:
    q(t) = high
```

任务进度规则：

```text
progress += frequency_scale
```

功耗缩放规则：

```text
P_dvfs = P_high * voltage_scale^2 * frequency_scale
```

### 3.3 与现有仿真器的衔接

第10轮在 `SchedulerResult` 中新增可选字段：

```python
runtime_effect_by_core: dict[str, DecisionRuntimeEffect] | None
```

其中 `DecisionRuntimeEffect` 包含：

- `progress_slots`：该时隙对任务块推进的高频等效 slot 数。
- `compute_power_w`：该时隙调度动作实际产生的计算功耗。

如果调度器不提供该字段，仿真器仍使用第8轮默认逻辑：每个运行决策推进 1 个 slot，并使用任务块原始功耗。因此该扩展兼容已有调度器。

### 4.4 测试项具体说明

1. `test_fcfs_dvfs_does_not_skip_queue_head_task`

   该测试构造两个同一时刻释放的单块任务 `T0` 和 `T1`，并给系统安全的温度和电量。调度器按 FCFS 排序后应选择队首任务 `T0`，而不是因为 `T1` 也可运行就跳到后续任务。测试同时检查安全状态下频率档位为 `high`。它验证的是 DVFS 基线只做设备级频率调节，不具备任务重排能力。

2. `test_high_temperature_selects_low_frequency`

   该测试直接调用 `select_frequency_level(...)`，构造温度 `65` 摄氏度、电量安全的系统状态。由于温度超过临界阈值 `T_crit=60`，预期返回低频档 `low`。它验证的是热压力达到临界状态时，DVFS 会主动降频以减少计算功耗和产热。

3. `test_low_energy_selects_low_frequency`

   该测试构造温度安全但电量为 `35 J` 的系统状态。由于电量低于临界阈值 `E_crit=40 J`，预期返回低频档 `low`。它验证的是电量不足时，即使温度安全，DVFS 也会选择低频以降低瞬时能耗。

4. `test_safe_thermal_electric_state_selects_high_frequency`

   该测试构造温度 `25` 摄氏度、电量 `100 J` 的安全状态，二者均未触发告警或临界阈值。预期选择 `high`。它验证的是在热-电资源充足时，DVFS 不会不必要地降频，从而保留高吞吐执行能力。

5. `test_dvfs_progress_and_power_follow_selected_frequency_level`

   该测试让系统处于高温状态，从而选择低频档。任务块高频执行时长为 4 个 slot，低频 `frequency_scale=0.5`，因此调度一个时隙后剩余工作量应从 4 降到 3.5。任务块原始功耗为 10 W，低频功耗应按 `0.75^2 * 0.5` 缩放。测试同时检查调度器内部记录和 `SchedulerResult.runtime_effect_by_core` 中传给仿真器的运行效果。它验证的是 DVFS 不只是打标签，还真实改变任务推进速度和计算功耗。

6. `test_tebs_modules_are_importable`

   该测试遍历并导入 `tebs` 包下所有模块。第10轮首次测试时发现 `DEFAULT_FREQUENCY_LEVELS` 初始化早于私有校验函数定义，导致导入阶段 `NameError`。已将校验函数前移，导入测试通过。该测试用于防止模块初始化顺序或包导出错误。
