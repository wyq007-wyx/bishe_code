## 2. 本轮目标

实现 TCN 动作约束过滤模块。学习模型输出不能直接进入仿真器，需要先过滤释放时间、前驱、核心兼容、核心容量、能量和热约束，保证 TCN 与 Hybrid 方法具备基本安全性。

更新文件：

- `tebs_scheduler/src/tebs/learning/__init__.py`

主要接口：

- `ConstraintFilter`：从按分数排序的 `TcnActionProposal` 中选择每核心一个可执行动作。
- `ConstraintFilterResult`：返回最终 `ScheduleDecision`、保留动作、拒绝动作、动作可行率和保留率。
- `RejectedAction`：记录被拒绝候选及原因。
- `safe_idle_filter_result(...)`：生成全 idle 的安全过滤结果。

过滤规则：

- 未知核心、未知任务、未知任务块拒绝。
- 未释放任务或任务块拒绝。
- 前驱任务块未完成时拒绝后继块。
- 同一时隙同一任务块不能被多个核心重复分配。
- 核心不在任务块 `duration_by_core` 中时拒绝。
- 聚合计算功耗导致能量低于 `E_min` 时拒绝。
- 聚合计算功耗导致温度超过 `T_max` 时拒绝。

### 4.4 测试项具体说明

1. `test_constraint_filter_rejects_predecessor_violation_and_selects_ready_block`

   构造一个两块任务，block 1 依赖 block 0。测试故意给 block 1 更高 TCN 分数，验证过滤器不会盲目接受高分动作，而是记录 `predecessor_incomplete` 并选择已释放且前驱满足的 block 0。

2. `test_constraint_filter_falls_back_to_idle_when_energy_is_infeasible`

   构造无太阳能输入、低剩余能量且 `E_min` 接近当前电量的场景。测试验证非 idle 动作会因为 `energy_infeasible` 被拒绝，最终返回 idle 决策，避免学习模型把系统推入能量违约。
