### 3.2 `visualization.py` 实现内容

新增主要对象与接口：

- `VisualizationError`：可视化输入为空、字段缺失或无法生成图表时抛出清晰错误。
- `FigureOutputs`：记录一组实验图表输出路径。
- `render_gantt_chart(...)`：生成 slot 级甘特图。
- `render_energy_temperature_curve(...)`：生成电量-温度曲线图。
- `render_power_curve(...)`：生成计算功耗、基础功耗、总功耗和太阳能输入曲线图。
- `render_solver_statistics(...)`：生成求解器状态比例统计图。
- `render_metrics_bar_chart(...)`：生成指标柱状图。
- `generate_experiment_figures(...)`：为单个方法运行生成标准图表集合。
- `state_trace_to_energy_temperature_rows(...)`：输出同时包含 `energy_j` 与 `energy_wh` 的表格数据。
- `power_rows_from_schedule(...)`：从调度轨迹、任务和环境数据重建每时隙功耗数据。

实现特点：

1. 不新增 `matplotlib` 或 `pandas` 等运行依赖，使用 Python 标准库直接写入 PNG。
2. 电量内部数据保留焦耳 `J`，绘图行额外提供 `Wh = J / 3600`。
3. 甘特图颜色按 `task_id:block_id` 稳定哈希生成，固定输入下图表可复现。
4. DVFS 调度若带有 `frequency_level`，功耗曲线会按高/中/低频档近似缩放计算功耗。
5. 空 `schedule_trace`、空 `state_trace`、空 `solver_trace` 会抛出 `VisualizationError`，便于调用端定位问题。

### 4.4 测试项具体说明

1. `test_render_visualization_png_files`

   构造一个包含两个核心、一个任务和三段状态的最小可视化样例，分别调用甘特图、电量温度图、功耗图和求解器统计图渲染函数。测试检查每个输出路径存在、文件非空，并且文件头符合 PNG 格式，验证图表生成链路可用。

2. `test_energy_plot_rows_keep_joule_and_add_wh`

   手工构造 `3600 J` 和 `7200 J` 两个状态点，调用 `state_trace_to_energy_temperature_rows(...)`。测试确认输出中仍保留 `energy_j`，同时新增 `energy_wh`，且转换值分别为 `1.0 Wh` 和 `2.0 Wh`。

3. `test_power_rows_reconstruct_compute_base_total_and_harvested_power`

   构造任务功耗、调度决策和轨道环境。测试确认第 0 时隙计算功耗为任务块在 `hp_0` 上的 `10 W`，基础功耗为 `1 W`，总功耗为 `11 W`，太阳能输入为 `8 W`。该测试验证功耗曲线不是随意画图，而是根据 trace 和任务参数重建数据。

4. `test_generate_experiment_figures_returns_standard_paths`

   调用统一入口 `generate_experiment_figures(...)`，输入调度、状态、指标和求解轨迹，预期返回 `FigureOutputs`，并生成甘特图、电量温度图、功耗图、求解器统计图和指标图。该测试覆盖后续第17轮批量运行器对可视化模块的调用方式。

5. `test_empty_visualization_inputs_raise_clear_errors`

   分别传入空 `schedule_trace`、空 `state_trace` 和空 `solver_trace`，预期抛出 `VisualizationError`，且错误信息中包含对应输入名。该测试验证异常语义清晰，避免批量实验阶段静默生成空图。
