### 3.2 `gurobi_adapter.py` 实现内容

新增主要对象与接口：

- `GurobiSolveParams`：封装 `TimeLimit`、`MIPGap`、`Threads`、`OutputFlag`。
- `GurobiSolveResult`：封装标准化求解结果，包括状态、耗时、MIPGap、目标值、best bound、节点数和可行解标记。
- `is_gurobi_available()`：检测当前环境是否安装 `gurobipy`。
- `require_gurobi()`：懒加载 `gurobipy`，不可用时抛出 `GurobiUnavailableError`。
- `apply_gurobi_params(...)`：统一设置 Gurobi 参数。
- `map_gurobi_status(...)`：把 Gurobi 数字状态码映射为稳定字符串。
- `solve_gurobi_model(...)` / `optimize_gurobi_model(...)`：构建、求解并抽取标准结果。
- `extract_solve_result(...)`：从 Gurobi model 中读取求解状态和统计量。

状态码映射覆盖：

```text
2  -> OPTIMAL
3  -> INFEASIBLE
4  -> INF_OR_UNBD
5  -> UNBOUNDED
9  -> TIME_LIMIT
11 -> INTERRUPTED
13 -> SUBOPTIMAL
```

### 3.3 与现有模型的衔接

`GurobiSolveResult.to_solver_trace(...)` 可直接转换为第1轮已有的 `SolverTrace`，供仿真器和指标模块记录滚动时域每个时隙的求解信息。

### 4.4 测试项具体说明

1. `test_apply_gurobi_params_sets_time_limit_and_gap`

   该测试使用 fake model 记录 `setParam(...)` 调用，不依赖真实 Gurobi。它验证适配层会把 `TimeLimit=3.5`、`MIPGap=0.02`、`Threads=2`、`OutputFlag=1` 正确传给模型。

2. `test_status_mapping_covers_core_gurobi_statuses`

   该测试直接调用 `map_gurobi_status(...)`，检查论文实验最常用的 `OPTIMAL`、`INFEASIBLE`、`TIME_LIMIT` 三类状态映射。它保证后续统计最优率、超时率和不可行率时使用稳定字符串。

3. `test_toy_milp_solves_when_gurobi_is_available`

   该测试构造一个最小二进制 MILP：变量 `x` 必须满足 `x >= 1`，目标最小化 `x`。有可用 Gurobi 与 license 时，预期求得 `OPTIMAL` 且目标值为 1。当前环境没有可用 `gurobipy`，测试按计划自动 skip。

4. `test_tebs_modules_are_importable`

   该测试遍历导入 `tebs` 包下所有模块。第12轮的重点是确认 `gurobi_adapter.py` 使用懒加载，不会在导入阶段强制要求安装 Gurobi。
