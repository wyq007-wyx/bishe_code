# 高校实验室任务参数测试计划

生成日期：2026-06-02

本文档基于 `docs/任务参数公开依据.md`，给出一套以树莓派和服务器为主的可落地测试计划。目标是把第3轮 `task_factory.py` 中的任务时长和功耗从“初始仿真设定”升级为“公开输入数据 + 实验室硬件 profiling 得到的标定参数”。

## 1. 测试目标

1. 对 7 类任务分别选取公开可获得测试输入。
2. 在树莓派和服务器上运行可复现实验。
3. 记录任务块运行时间、负载功耗、空闲功耗、动态功耗和能耗。
4. 将实测结果映射为 `task_factory.py` 可使用的：
   - `duration_slots`
   - `power_watts`
   - 高性能核/低功耗核的相对速度和功耗倍率
5. 输出可复查的 CSV 原始结果和参数汇总表。

推荐映射公式：

```text
duration_slots = ceil(P95_runtime_seconds / delta_t_seconds)
dynamic_power_watts = max(0, average_load_power_watts - average_idle_power_watts)
energy_joule = dynamic_power_watts * mean_runtime_seconds
```

当前项目默认 `delta_t_seconds = 60`。建议用 P95 运行时间映射 slot，避免偶然快样本让仿真参数过于乐观。

## 2. 测试硬件

| 角色 | 推荐硬件 | 用途 | 是否必需 |
|---|---|---|---|
| 低功耗边缘侧 | Raspberry Pi 4B 或 Raspberry Pi 5，4GB/8GB RAM | 模拟低功耗星载计算节点，测试轻量推理、压缩和小块处理 | 必需 |
| 服务器 CPU | Linux 服务器，多核 CPU，32GB+ RAM | 跑全部任务的 CPU 基准和重数据预处理 | 必需 |
| 服务器 GPU | NVIDIA GPU，如 RTX 3060/3090/A5000/A6000 等 | 测深度学习推理和高性能核参考参数 | 强烈建议 |
| 树莓派功耗测量 | USB-C 功率计、INA219 或 INA226 | 测树莓派整机空闲和负载功耗 | 强烈建议 |
| 服务器功耗测量 | `nvidia-smi`、Intel RAPL、插座功率计 | 测 GPU/CPU/整机功耗 | 建议 |

如果服务器没有 GPU，可以先完成树莓派和服务器 CPU 版标定，但实验报告必须标注“GPU 参数未测，当前高性能核仅由服务器 CPU 近似”。

## 3. 软件环境

| 平台 | 建议环境 |
|---|---|
| 树莓派 | Raspberry Pi OS 64-bit、Python 3.10+、OpenCV、NumPy、PyTorch CPU 或 ONNX Runtime |
| 服务器 CPU/GPU | Ubuntu 20.04/22.04、Conda 或 Docker、Python 3.10+、PyTorch、CUDA、OpenCV、GDAL/Rasterio |
| SAR 后端 | ESA SNAP Desktop/GPT、SNAP Sentinel-1 Toolbox、Java Runtime |
| 压缩任务 | Python 图像压缩库、JPEG2000/OpenJPEG、CCSDS 122/123 开源实现或可替代命令行工具 |

每次测试必须记录：

| 字段 | 示例 |
|---|---|
| OS | Ubuntu 22.04 / Raspberry Pi OS 64-bit |
| CPU | Raspberry Pi 5 Cortex-A76 / Intel Xeon |
| GPU | RTX 3090 / 无 |
| 内存 | 8GB / 64GB |
| Python | 3.10.13 |
| CUDA | 11.8 |
| 框架 | PyTorch 2.1.0 / ONNX Runtime |
| 模型代码版本 | Git commit 或 release tag |

输入选择原则：

1. 优先选无需商业授权、可公开下载或可学术申请的数据。
2. 每类任务先固定 30-100 个样本，避免全量数据过大导致测试不可控。
3. 每个样本保存 `sample_id`、数据集名、原始文件名、裁剪坐标和预处理脚本参数。
4. 如果某数据集需要账号或申请，文档中记录申请入口和下载日期。

## 5. 七类任务测试方案

## 6. 功耗测量方法

| 平台 | 推荐方法 | 记录内容 |
|---|---|---|
| 树莓派 | USB-C 功率计、INA219、INA226 | 空闲功耗、任务负载功耗、采样间隔 |
| NVIDIA GPU | `nvidia-smi --query-gpu=timestamp,power.draw,utilization.gpu --format=csv -lms 200` | GPU 功耗和利用率 |
| 服务器 CPU | Intel RAPL、`powerstat`、插座功率计 | CPU 包功耗或整机功耗 |
| 无专用测量设备 | 至少记录运行时间，不把功耗写为实测 | 功耗字段标记为 `not_measured` |

推荐测量步骤：

1. 启动系统后静置 3-5 分钟，记录空闲功耗。
2. 每个任务样本先 warm-up 5 次，不计入统计。
3. 正式测试每个样本重复 10 次。
4. 同步采集功耗，树莓派建议 1-5 Hz，GPU 建议 5 Hz 或更高。
5. 取 `load_power_mean - idle_power_mean` 作为动态功耗。

## 8. 参数回写建议

不要直接把单次测量结果写入源码。建议新增：

```text
configs/task_profiles.yaml
experiments/task_profiling/task_profile_results.csv
experiments/task_profiling/task_profile_summary.csv
docs/任务参数实测标定说明.md
```

其中 `configs/task_profiles.yaml` 可采用：

```yaml
task_profiles:
  T1:
    name: cloud_detection
    block_count_range: [4, 8]
    weight: 2.0
    high_power: false
    raspberry_pi:
      duration_slots_range: [1, 1]
      power_watts_range: [3.8, 5.2]
    server_gpu:
      duration_slots_range: [1, 1]
      power_watts_range: [18.0, 32.0]
```

后续可让 `task_factory.py` 从该配置读取实测 profile，而不是继续硬编码初始仿真参数。

## 9. 分阶段执行计划

| 阶段 | 目标 | 任务 | 产物 |
|---|---|---|---|
| 第1阶段 | 快速跑通测量链路 | T1、T6、T3 小样本 | 初版测试脚本、功耗采样脚本、CSV 样例 |
| 第2阶段 | 覆盖主要深度学习任务 | T2、T4、T5 | GPU/CPU/树莓派对比数据 |
| 第3阶段 | 覆盖 SAR 后端重流程 | T7 | SNAP 子流程耗时和功耗数据 |
| 第4阶段 | 汇总并校准仿真参数 | 全部任务 | `task_profile_summary.csv`、`任务参数实测标定说明.md` |

## 10. 风险与处理

| 风险 | 处理 |
|---|---|
| 数据集过大，下载慢 | 先下载小样本或只裁剪固定 ROI |
| 树莓派跑不动大模型 | 使用 ONNX/TFLite/更小输入，只作为低功耗近似平台 |
| 服务器无 GPU | 完成 CPU 标定，GPU 字段标记缺失 |
| 功耗测量设备不可用 | 时间参数仍可测，功耗字段不得伪造 |
| SAR SLC 全流程过重 | 只测单 burst、单 subswath 或 ROI 子集 |

## 11. 验收标准

1. 每类任务至少有 30 个有效样本。
2. 每个有效样本至少重复运行 10 次。
3. 每类任务至少有一个硬件平台的时间参数。
4. 如果声明功耗参数，必须提供测量方法和原始采样文件。
5. 所有参数均可追溯到公开输入来源、运行脚本和硬件环境。
