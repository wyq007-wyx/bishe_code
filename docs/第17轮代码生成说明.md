### 3.2 `experiment_runner.py` 实现内容

新增主要对象与接口：

- `ExperimentRunnerError`：批量实验配置或方法名非法时抛出清晰错误。
- `ExperimentBatchConfig`：批量实验配置，包含场景、方法、随机种子、输出目录、任务数量、仿真时长和是否生成图表。
- `ExperimentRunResult`：单个场景-方法-种子运行结果，包含 summary、输出路径、仿真结果和图表路径。
- `ExperimentBatchResult`：批量运行结果，包含所有单次运行结果、`summary.csv` 和 `solver_summary.csv` 路径。
- `available_method_names()`：返回运行器支持的方法名。
- `normalize_method_name(...)`：归一化方法别名，如 `FCFS-DVFS` -> `fcfs_dvfs`，`rhc` -> `rhc_milp_gurobi`。
- `create_scheduler(...)`：按方法名创建新的调度器实例。
- `run_single_experiment(...)`：运行一个场景、一个方法和一个随机种子。
- `run_experiment_batch(...)`：批量运行多个场景、随机种子和方法组合。

当前支持的方法：

```text
safe_idle
fcfs_dvfs
fcfs_intermittent
fcfs_gurobi
rhc_milp_gurobi
```

默认方法为：

```text
fcfs_dvfs
fcfs_intermittent
```

输出文件结构：

```text
output_dir/
  metrics/
    summary.csv
    solver_summary.csv
  schedules/
    <scenario>_seed<seed>_<method>_schedule.csv
  states/
    <scenario>_seed<seed>_<method>_state.csv
  solver/
    <scenario>_seed<seed>_<method>_solver_trace.csv
  figures/
    <scenario>_seed<seed>_<method>/
      gantt_<method>.png
      energy_temperature_<method>.png
      power_<method>.png
      metrics_<method>.png
      solver_statistics_<method>.png  # 仅当 solver_trace 非空时生成
```

实现特点：

1. 每个 method 都通过 `create_scheduler(...)` 创建新的调度器实例，避免复用规则基线内部进度状态。
2. 同一场景和 seed 下，各方法共享相同任务集和环境，保证对比公平。
3. 固定 seed 后任务集、调度结果、summary 输出可复现。
4. `summary.csv` 汇总调度性能、安全约束和求解器统计字段。
5. `solver_summary.csv` 独立汇总求解器最优比例、可行比例、超时比例、求解时间和 MIPGap 等字段。
6. 即使某方法没有求解器轨迹，也会写入空 `solver_trace.csv` 和零值求解器汇总，方便后续批处理读取。
7. 图表生成复用第16轮 `visualization.py`，可通过 `generate_figures=False` 关闭。

### 4.4 测试项具体说明

1. `test_experiment_runner_runs_minimal_batch_and_writes_summaries`

   使用 `S1_light`、seed `7`、两个任务、八个时隙，运行 `safe_idle` 和 `fcfs_dvfs` 两个方法。测试检查批量结果包含两个 run，`metrics/summary.csv` 和 `metrics/solver_summary.csv` 存在，summary 中包含两个独立方法，并确认每个 run 都输出 schedule、state、solver trace 和图表文件。

2. `test_experiment_runner_gives_each_method_independent_schedule_file`

   使用 `safe_idle` 和 `fcfs_intermittent` 两个方法运行同一场景。测试检查两个 `schedule_csv` 路径不同且文件存在，验证批量运行器不会让不同方法互相覆盖输出，也不会复用同一个调度器实例。

3. `test_experiment_runner_fixed_seed_is_reproducible`

   用相同配置分别输出到 `run_a` 和 `run_b` 两个目录，关闭图表以聚焦数值结果。测试读取两次生成的 `summary.csv`，要求内容完全一致。该测试验证任务生成、调度执行和指标汇总在固定 seed 下可复现。

4. `test_experiment_runner_method_registry_and_aliases`

   检查方法注册表包含 `fcfs_dvfs` 和 `rhc_milp_gurobi`，并验证 `FCFS-DVFS`、`rhc` 等用户常用写法会归一化为内部方法名。该测试保证命令行或脚本调用时不容易因为大小写和连字符差异失败。

5. `test_unknown_method_raises_clear_error`

   传入不存在的 `missing_method`，预期 `run_experiment_batch(...)` 抛出 `ExperimentRunnerError`，错误信息包含 `Unknown method_name`。该测试保证批量实验配置错误能尽早暴露，而不是在仿真中后期产生难以定位的失败。
