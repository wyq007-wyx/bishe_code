### 3.2 `models.py` 实现内容

实现了第1轮要求的共享数据结构：

- `Task`
- `TaskBlock`
- `Core`
- `SystemState`

并将 `ScheduleTrace` 的字段统一为 `decisions: list[ScheduleDecision]`。

### 3.3 关键校验逻辑

- 任务块核心映射校验：
  - `duration_by_core` 与 `power_by_core` 核心集合必须一致。
  - 在 `Task.core_ids` 给定时，每个任务块核心集合必须是其子集（支持多阶段差异核心适配）。
  - 可选开启 `require_uniform_block_core_ids=True`，要求任务内所有块使用一致核心集合。
- 时间合法性校验：
  - `release_time <= deadline`。
- 前驱顺序校验：
  - `predecessor_block_id < block_id`。
  - 且必须指向任务内已出现的更早块。
- 调度动作表达校验：
  - `ScheduleDecision.idle(...)` 表示核心空闲。
  - `ScheduleDecision.run(...)` 表示核心执行任务（支持任务级和任务块级两种粒度）。

### 3.4 核心代码逻辑说明

`models.py` 采用“构造即校验”的实现方式：对象一旦创建成功，就满足后续模块可直接依赖的基础约束。

核心逻辑如下：

1. `TaskBlock`（任务块原子单元）
   - 校验 `release_time <= deadline`；
   - 校验 `duration_by_core` 与 `power_by_core` 的核心集合一致；
   - 校验 `predecessor_block_id < block_id`，避免同层或逆序前驱。
2. `Task`（任务聚合单元）
   - 要求至少一个 `TaskBlock`；
   - 校验所有块 `task_id` 一致、`block_id` 唯一；
   - 校验前驱必须指向已出现的更早块，保证顺序合法。
   - 不强制 `Task.deadline` 等于最后一个任务块的 `deadline`；
   - 提供 `Task.single_block(...)`，用于把不划分任务块的对比方案统一表示为单块任务。
3. `Core`（异构核心建模）
   - `core_type` 统一为 `high_performance`/`low_power`；
   - 新增 `build_cores_from_type_counts(...)`，可按两类核心数量生成核心列表。
4. `ScheduleDecision`（统一调度动作）
   - 空闲动作：`is_idle=True` 且不允许携带任务字段；
   - 执行动作：`is_idle=False` 且必须携带 `task_id`，`block_id` 可选：
     - `block_id=None`：任务级决策（规则基线）
     - `block_id=int`：任务块级决策（块级方法）
5. `ScheduleTrace`（时隙动作记录）
   - 要求 `decision.time_slot` 与轨迹 `time_slot` 一致；
   - 限制同一时隙每个核心最多一条决策，避免冲突分配。
6. `SystemState` / `SolverTrace`
   - `SystemState` 保证状态字段合法（例如电量非负）；
   - `SolverTrace` 统一承载求解状态、耗时、`MIPGap` 等统计输入。

### 3.5 架构说明

第一轮采用“领域模型先行”的架构策略，把共享数据契约固定下来，再推进后续模块。

1. 工程分层
   - `tebs_scheduler/src/tebs/models.py`：领域数据模型与约束边界；
   - `tebs_scheduler/tests/test_models.py`：模型契约测试；
   - `tebs_scheduler/tests/test_imports.py`：包导入与工程骨架有效性测试。
2. 依赖方向
   - 后续模块（`task_factory`、`environment`、`scheduler`、`simulator`、`metrics`）只依赖 `models.py`，不反向依赖。
3. 架构价值
   - 在第一轮提前统一字段命名和合法性规则；
   - 降低后续轮次接口漂移和跨模块返工概率；
   - 让仿真闭环和 Gurobi/学习模块能共享同一份数据语义。

## 4. 测试与验收

执行命令：

```bash
cd tebs_scheduler
pytest tests/test_imports.py tests/test_models.py
```

覆盖了第1轮计划中的测试重点：

1. 任务块核心映射覆盖与一致性；
2. `release_time <= deadline`；
3. predecessor 顺序合法；
4. `SystemState` 的电量、温度、时刻字段；
5. `ScheduleDecision` 对“执行/空闲”的表达能力。

补充：`SystemState` 已增加温度合法性校验，要求温度为有限数值且不低于绝对零度（`-273.15℃`）。
补充：`models.py` 已增加 `build_cores_from_type_counts(...)`，用于按高性能核/低功耗核数量生成核心列表，便于后续配置文件直接驱动核心构建。
补充：`SystemState` 只校验 `energy_joule >= 0`，不校验安全电量下限 `E_min`；`E_min` 留给后续能量模型记录 `energy_violation`。
