# 任务参数公开依据

生成日期：2026-06-02

本文档用于约束 `tebs_scheduler/src/tebs/task_factory.py` 中 7 类任务参数的来源边界。核心原则是：公开资料能支撑任务类型、公开数据集、典型处理流程、公开运行环境和相对计算负载；但公开资料通常不能直接给出本项目目标星载平台上的逐任务块 `duration_slots` 与 `power_watts`，因此这些数值只能作为仿真实验的可调参数，后续必须通过统一 profiling 流程重新标定。

## 1. 当前代码参数

| ID | 任务类型 | 代码中的块数 | 权重 | 高功耗组 | 高性能核时长范围 slot | 高性能核功耗范围 W |
|---|---|---:|---:|---|---:|---:|
| T1 | 云检测 | 4-8 | 2 | 否 | 2-4 | 7-10 |
| T2 | 云去除与压缩 | 4 | 2 | 否 | 2-5 | 6-11 |
| T3 | SAR 船舶检测 | 6-10 | 5 | 是 | 4-7 | 16-24 |
| T4 | 光学目标检测 | 4-8 | 3 | 否 | 3-5 | 10-15 |
| T5 | 变化检测 | 4-6 | 5 | 是 | 3-6 | 15-22 |
| T6 | 图像压缩 | 3-6 | 1 | 否 | 1-3 | 4-8 |
| T7 | SAR 后端处理 | 6-10 | 4 | 是 | 5-8 | 18-26 |

注意：上表中的 `slot` 与 `W` 不是公开论文逐项实测值，而是第3轮任务工厂中用于形成轻/中/重负载差异的仿真参数。本文档只说明哪些公开资料能支撑这些参数的方向性设置，哪些部分必须重新测量。

## 5. 对第3轮任务参数的约束建议

1. 任务类型与块数：可以继续采用当前 7 类任务和块数范围，因为公开资料明确支持这些任务可按 tile、patch、ROI、burst、code-block 或处理阶段拆分。
2. 权重：`T3/T5` 权重最高、`T7` 次高、`T6` 最低的方向是合理的，因为 SAR 船舶检测和灾害变化检测具有更强时效价值，压缩更偏下传准备与资源填谷；但权重仍属于实验目标函数设定，不是公开数据集固有属性。
3. 高功耗分组：`T3/T5/T7` 归为高功耗组有公开任务复杂度支持；`T4` 应保持中高负载，不建议归入低功耗组。
4. 时长与功耗：当前 `hp_duration_range` 和 `hp_power_range_w` 只应写为“初始仿真参数”。论文或实验报告中不能声称它们来自公开实测。
5. 后续标定：建议新增 `docs/任务profiling方案.md` 或配置文件，把每个任务类型绑定到公开代码、公开数据 patch、输入大小、硬件、batch size、模型版本、平均推理/处理时间、平均功耗和峰值功耗。

## 6. 推荐 profiling 口径

| 字段 | 记录方式 |
|---|---|
| 数据来源 | 数据集名、下载链接、许可证、样本 ID 或区域 ID |
| 任务块粒度 | tile/patch/ROI/burst/code-block/stage 的尺寸与数量 |
| 模型或算法 | 模型名、代码仓库、commit、权重文件、预处理流程 |
| 运行环境 | CPU、GPU/VPU/FPGA、内存、操作系统、Python/CUDA/框架版本 |
| 时间指标 | 单块平均时间、P50/P95/P99、冷启动是否计入、batch size |
| 功耗指标 | 平均功耗、峰值功耗、测量工具、采样频率、是否包含平台基础功耗 |
| 映射到仿真 | `duration_slots = ceil(real_seconds / delta_t_seconds)`，`power_watts = measured_dynamic_power_w` |

只有完成上述 profiling 后，`task_factory.py` 中的 `hp_duration_range` 和 `hp_power_range_w` 才能从“初始仿真设定”升级为“公开数据 + 目标硬件实测参数”。
