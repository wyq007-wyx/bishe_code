## 3. 本轮生成结果

新增主要接口：

- `BaseScheduler`：所有调度器的抽象基类。
- `SchedulerResult`：单时隙调度输出，包含 `decisions` 和可选 `solver_trace`。
- `SafeIdleScheduler`：安全空闲策略，每个核心返回 idle。
- `make_idle_decisions(...)`：生成每核心一个 idle 动作。
- `validate_scheduler_result(...)`：校验返回动作中的时间、核心、任务和任务块引用。

`decide(...)` 统一输入：

```text
current_time
tasks
cores
system_state
environment_window
```

统一输出为：

```text
SchedulerResult(decisions, solver_trace=None)
```

### 4.4 测试项具体说明

1. `test_safe_idle_scheduler_returns_one_idle_decision_per_core`

   该测试构造 2 个核心和 1 个 toy 任务，然后调用 `SafeIdleScheduler.decide(...)`。测试检查返回动作数量是否等于核心数量、每个动作是否都是 idle、动作中的核心 ID 集合是否与输入核心集合一致，并进一步用 `validate_scheduler_result(..., require_all_cores=True)` 做合法性验证。它验证的是统一调度接口能返回标准 `SchedulerResult`，同时提供一个永远安全的基准调度器供仿真器烟测使用。

2. `test_scheduler_result_rejects_unknown_core_id`

   该测试手工构造一个非 idle 调度动作，让它引用不存在的核心 `bad`。调用 `validate_scheduler_result(...)` 时，预期抛出 `SchedulerError`。它验证的是调度器输出不会悄悄接受未知硬件资源，避免后续仿真器在读取任务块功耗或时长时才失败。

3. `test_scheduler_result_rejects_unknown_task_block`

   该测试手工构造一个调度动作，让它引用存在的任务 `T1`，但引用不存在的任务块 `block_id=99`。预期校验阶段抛出 `SchedulerError`。它验证的是非 idle 决策必须指向真实任务块，后续 RHC-MILP 或规则基线输出动作时如果产生非法 block ID，会在统一接口层被拦截。

4. `test_tebs_modules_are_importable`

   该测试确认 `scheduler_base.py` 可被包导入测试导入。对第7轮来说，它保证抽象基类、默认空闲调度器和校验函数没有导入副作用，也不依赖后续未实现的具体调度器。
