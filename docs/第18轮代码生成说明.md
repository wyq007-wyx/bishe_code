## 2. 本轮目标

实现 TCN 监督学习数据集构建模块，将调度轨迹、系统状态、任务集合、核心集合和未来环境窗口转换为固定长度的 TCN 输入特征与每核心动作标签。

- `docs/第18轮代码生成说明.md`

更新文件：

- `tebs_scheduler/src/tebs/__init__.py`

主要接口：

- `TcnFeatureSpec`：记录 `horizon_slots`、`max_tasks`、`max_blocks_per_task`、`core_ids` 和特征名。
- `ActionLabel`：记录每个核心在某时隙的监督动作标签，`0` 表示 idle，非零表示任务块动作。
- `TcnTrainingSample`：一条训练样本，包含 `H x F` 特征窗口和每核心标签。
- `TcnDataset`：样本集合，提供 `feature_dim` 和 `as_xy()`。
- `build_feature_names(...)`：生成固定特征名契约。
- `build_feature_window(...)`：构建推理和训练共用的固定窗口特征。
- `build_dataset_from_traces(...)`：从仿真轨迹生成监督学习数据集。

### 4.4 测试项具体说明

1. `test_dataset_builder_emits_fixed_windows_and_labels`

   构造两个核心、两个任务和两条调度轨迹。第 0 时隙 `hp_0` 执行 `T0` 的 block 0，`lp_0` idle；第 1 时隙 `hp_0` 执行 `T0` 的 block 1，`lp_0` 执行 `T1`。测试检查 `build_dataset_from_traces(...)` 是否输出固定 `H x F` 特征窗口，并把每核心决策映射到稳定动作标签。

2. `test_feature_name_contract_matches_task_and_core_counts`

   直接调用 `build_feature_names(...)`，验证生成的字段名包含系统能量、核心类型和任务 deadline slack 等关键特征，并检查特征数量与 `max_tasks`、核心数量一致。该测试保证后续 TCN 训练和推理使用同一特征顺序。
